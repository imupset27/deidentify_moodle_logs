## 1. Overview

This entry contains the R script used to de-identify the Moodle activity logs of the graduate level course before public release. 
It replaces person identifiers with pseudonymous codes and leaves timestamps and activity names unchanged. 

The script is shared for **transparency**. It cannot be re-run by others on the original data, because 
the raw Moodle export and the secret key are not shared for privacy reasons. 
It can be adapted to other Moodle log exports with the same column structure.

## 2. What the script does

| Step | Action |
|---|---|
| 1 | Reads the raw Moodle log CSV, with all columns as text and whitespace trimmed |
| 2 | Builds a name-to-code map. Codes are `S` + 8 hex characters (students) or `T` + 8 hex characters (staff/non-student accounts), computed as HMAC-SHA256 of the name with a secret key and truncated |
| 3 | Optionally removes rows generated by staff, administrator, and test accounts (`drop_staff_rows`) |
| 4 | Maps Moodle numeric user IDs found in `Description` ("user with id '1234'") to the same codes |
| 5 | Replaces `User full name` and `Affected user` with `user_id` and `affected_user_id` |
| 6 | Replaces person names inside `Description`, `Event context`, and `Origin` (case-insensitive, whole-word match) |
| 7 | Masks IPv4 addresses and e-mail addresses in `Description`; drops the `IP address` column |
| 8 | Runs safety checks (remaining names, remaining numeric IDs, unmapped IDs, rows without `user_id`) |
| 9 | Writes the de-identified CSV, a report of counts and checks, and `sessionInfo()` |

**Not changed:** `Time`, `Component`, `Event name`, and activity names in `Event context`.

## 5. Usage (for adapting to your own logs)

Folder layout:

```
project_folder/
├── 01_deidentify_moodle_logs.R
├── .moodle_secret                 (never share)
├── raw/
│   └── <your Moodle log export>.csv   (never share)
└── data/                          (created by the script)
```

1. Create the secret key once, a random string of at least 20 characters:
   ```r
   writeLines(paste(sample(c(letters, LETTERS, 0:9), 40, TRUE), collapse = ""), ".moodle_secret")
   ```
   Back it up securely. Without it, the same codes cannot be regenerated.
2. Edit the **Settings** block at the top of the script: `raw_file`, `out_file`, `staff_names`, `drop_staff_rows`.
3. Run the script (in RStudio, or `Rscript 01_deidentify_moodle_logs.R`).
4. Check `data/deidentification_report.txt`. "Name matches left" and "Numeric IDs left" should both be 0.
5. Inspect a random sample of `Description` rows manually for nicknames, "Surname, First" order, and typos that exact matching misses.

## 6. Input and output columns

**Expected input columns** (standard Moodle log export): `Time`, `User full name`, `Affected user`, `Event context`, `Component`, `Event name`, `Description`, `Origin`, `IP address`. Different Moodle versions or languages may use other column names or description wording, so adjust the script if needed.

**Output columns:** `user_id`, `affected_user_id`, `Time`, `Event context`, `Component`, `Event name`, `Description`, `Origin`.

## 7. Limitations and security notes

- Pseudonymization is not anonymization. Retained exact timestamps and activity names can allow linkage by someone who knows when a student took part in an activity.
- Name matching is exact (case-insensitive, whole word). Nicknames, reordered names, and misspellings are not caught.
- The `Description` ID pattern assumes English-language Moodle text ("The user with id '...'").
- Anyone with the secret key can regenerate the codes from names. Keep the key private and out of version control (add `.moodle_secret` and `raw/` to `.gitignore`).
