**Entry type:** Code / software\

## 1. Overview

This entry contains the R script used to de-identify the Moodle activity logs **and the quiz grade exports** of the graduate level course before public release.
It replaces person identifiers with pseudonymous codes and leaves timestamps, activity names, and grades unchanged.

A single name-to-code key is built once from the raw log, so **a student has the same code in the log and in every grade file**, and the two datasets can be linked after sharing.

The script is shared for **transparency**. It cannot be re-run by others on the original data, because
the raw Moodle export, the grade exports, and the secret key are not shared for privacy reasons.
It can be adapted to other Moodle log and grade exports with the same column structure.

## 2. What the script does

The script runs in two parts that share one key. Each part can be switched on or off with `run_logs` and `run_grades`.

### Shared steps

| Step | Action |
|---|---|
| 1 | Reads the raw Moodle log CSV, with all columns as text and whitespace trimmed |
| 2 | Builds one name-to-code key from the full raw log (before staff rows are dropped). Codes are `S` + 8 hex characters (students) or `T` + 8 hex characters (staff/non-student accounts), computed as HMAC-SHA256 of the name with a secret key and truncated. The key also holds an accent-insensitive version of each name, used to match grade rows |

### Part A: Activity log

| Step | Action |
|---|---|
| A1 | Optionally removes rows generated by staff, administrator, and test accounts (`drop_staff_rows`) |
| A2 | Maps Moodle numeric user IDs found in `Description` ("user with id '1234'") to the same codes |
| A3 | Replaces `User full name` and `Affected user` with `user_id` and `affected_user_id` |
| A4 | Replaces person names inside `Description`, `Event context`, and `Origin` (case-insensitive, whole-word match) |
| A5 | Masks IPv4 addresses and e-mail addresses in `Description`; drops the `IP address` column |
| A6 | Runs safety checks (remaining names, remaining numeric IDs, unmapped IDs, rows without `user_id`) |
| A7 | Writes the de-identified log CSV and a report of counts and checks |

### Part B: Quiz grade exports

Every `.csv` in the `grades/` folder is processed (files already starting with `De-iden-` are skipped).

| Step | Action |
|---|---|
| B1 | Matches each row to the shared key using "First Last", then "Last First" (some exports have the two name fields swapped). Matching is case-insensitive, then accent-insensitive |
| B2 | Removes `Last name`, `First name`, and `Email address`, and adds `user_id` as the first column |
| B3 | Removes staff/non-student rows (`drop_staff_rows`) |
| B4 | Removes the trailing "Overall average" row (`keep_overall_row = FALSE`), because it would no longer match the remaining rows |
| B5 | Runs safety checks per file (remaining e-mail strings, remaining name matches) |
| B6 | Writes `De-iden-<original file name>.csv` for each file and a report of counts and checks |

A student who appears in a grade file but has no activity in the raw log has no code from the key. The script computes a code for that student in the same way (from "First Last"), counts the row as "Not found in log (coded anyway)" in the report, and lists the names on the **console only** (not in the report file). Check these rows, because a misspelled or differently ordered name would receive a code that does not match the log.

Finally, the script writes `sessionInfo()`.

**Not changed:**
- Log: `Time`, `Component`, `Event name`, and activity names in `Event context`.
- Grades: `Status`, `Started`, `Completed`, `Duration`, grades, and per-question marks.

## 5. Usage (for adapting to your own data)

Folder layout:

```
project_folder/
├── deidentify_moodle_logs_and_grades.R
├── .moodle_secret                      (never share)
├── raw/
│   └── <your Moodle log export>.csv    (never share)
├── grades/
│   └── <your quiz grade exports>.csv   (never share)
└── data/                               (created by the script)
    ├── logs_deidentified.csv
    ├── deidentification_report.txt
    ├── grades_deidentification_report.txt
    ├── sessionInfo.txt
    └── grades/
        └── De-iden-<original file name>.csv
```

1. Create the secret key once, a random string of at least 20 characters:
   ```r
   writeLines(paste(sample(c(letters, LETTERS, 0:9), 40, TRUE), collapse = ""), ".moodle_secret")
   ```
   Back it up securely. Without it, the same codes cannot be regenerated.
2. Edit the **Settings** block at the top of the script:
   - Inputs: `raw_file`, `grades_dir`
   - Outputs: `out_file`, `log_report_file`, `grades_out_dir`, `grades_prefix`, `grades_report_file`, `session_file`
   - Switches: `run_logs`, `run_grades`
   - Accounts and rows: `staff_names`, `drop_staff_rows`, `keep_overall_row`
3. Run the script (in RStudio, or `Rscript deidentify_moodle_logs_and_grades.R`). The raw log is needed even when only the grades are processed, because the key is built from it.
4. Check both reports in `data/`. "Name matches left", "Numeric IDs left" (log), and "E-mail strings left" (grades) should all be 0.
5. Check the console for students "NOT found in the raw log" and correct the spelling or add the activity so the codes match across files.
6. Inspect a random sample of `Description` rows manually for nicknames, "Surname, First" order, and typos that exact matching misses.

## 6. Input and output columns

**Expected log input columns** (standard Moodle log export): `Time`, `User full name`, `Affected user`, `Event context`, `Component`, `Event name`, `Description`, `Origin`, `IP address`. Different Moodle versions or languages may use other column names or description wording, so adjust the script if needed.

**Log output columns:** `user_id`, `affected_user_id`, `Time`, `Event context`, `Component`, `Event name`, `Description`, `Origin`.

**Expected grade input columns:** `Last name`, `First name`, and `Email address` are required (the script stops if any is missing). All other columns (for example `Status`, `Started`, `Completed`, `Duration`, grade and per-question marks) are kept as exported.

**Grade output columns:** `user_id` followed by all remaining input columns, minus `Last name`, `First name`, and `Email address`.

## 7. Limitations and security notes

- Pseudonymization is not anonymization. Retained exact timestamps, activity names, and grades can allow linkage by someone who knows when a student took part in an activity or what score a student received. Linking the log and the grade files makes this easier, not harder.
- Name matching is exact (case-insensitive, whole word; grade rows are also matched accent-insensitively and in swapped order). Nicknames, other reorderings, and misspellings are not caught.
- The `Description` ID pattern assumes English-language Moodle text ("The user with id '...'").
- Grade files are expected to use the English Moodle column names `Last name`, `First name`, `Email address`, and the row label "Overall average".
- A grade row with no match in the log still receives a code (see Section 2). This code matches the log only if the name is spelled exactly as it would be in the log.
- Any free-text columns in a grade file other than those listed above are not edited, apart from the name and e-mail checks reported per file.
- Anyone with the secret key can regenerate the codes from names. Keep the key private and out of version control (add `.moodle_secret`, `raw/`, and `grades/` to `.gitignore`).
- `staff_names` in the script contains real names. If the script is published, replace them with generic labels or read them from a private file, for example `staff_names <- readLines("private/staff_names.txt")`.
